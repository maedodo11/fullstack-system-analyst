# SQL-лаборатория: от JOIN к метрике

[Курс](../../../README.md) · [Проект](../../../project/README.md) · [Простой HAVING](../README.md)

**Среда:** Python 3.10+ с SQLite 3.25+ (оконные функции). Сторонние пакеты не нужны. Все имена синтетические. Команды выполнять из корня репозитория.

```bash
python examples/sql/lab/run.py --init /tmp/analyst-lab.sqlite
python examples/sql/lab/run.py --check exercises
python examples/sql/lab/run.py --check solutions
```

Первый вызов создаёт БД для открытия в SQL-клиенте; существующий файл не перезаписывается. Второй проверяет ваши решения из exercises/ и сначала завершится ошибкой — там заготовки. Третий проверяет разобранные решения. Проверки используют новую БД в памяти, чтобы попытки не влияли друг на друга.

## Данные и договорённости

5 пациентов, 3 врача, 9 слотов, 8 исторических записей и 3 сообщения доставки. Один пациент без записей, один город NULL, есть ничья в рейтинге, дубли события, отмена и повторное занятие слота. Времена хранятся единообразно как UTC ISO 8601 без дробных секунд. Текстовые сравнения допустимы только при таком согласованном формате.

Месяц отчёта — октябрь 2026 в Asia/Irkutsk. В упражнении это UTC+08:00: нижняя граница включена, верхняя исключена. Не использовать системную дату или часовой пояс компьютера. В PostgreSQL для реальных часовых зон применяйте timestamptz и преобразования по IANA zone, а не постоянное смещение для произвольного региона.

## Как разбирать ошибку

Сверьте фактические строки с [expected.json](expected.json), затем проверьте уровень детализации: одна строка запроса представляет пациента, запись или сообщение? JOIN с delivery_events может размножить записи. COUNT(*) после LEFT JOIN посчитает строку даже при отсутствии записи; COUNT(a.id) — только ненулевые ID. WHERE по правой таблице может удалить строки без совпадения.

Для задания 10 ноль означает «исходы были, неявок нет», NULL — «закрытых исходов нет». Их нельзя подменять друг другом без решения владельца метрики.

**Готовность:** все десять запросов проходят проверку, а вы можете объяснить результат для пустой группы, дубля и обеих временных границ. Проверки эталонных данных не доказывают корректность на любом наборе: самостоятельно добавьте ещё один пограничный случай.
