## 2. Пользовательская история

**Как** <роль>, **я хочу** <действие>, **чтобы** <ценность>.

### Acceptance Criteria (Gherkin)

```gherkin
Feature: <возможность>

  Scenario: Успешный сценарий
    Given <предусловие>
    When <действие>
    Then <ожидаемый результат с проверяемым критерием>

  Scenario: Ошибочный случай — <что не так>
    Given ...
    When ...
    Then <код ошибки, сообщение, поведение UI>
```

Покрыть минимум: happy path, валидация входа, права доступа, конкурентный случай (двойной клик/повтор), таймаут зависимости.

## 3. Описание потока

1. Основной поток (нумерованные шаги, экран → действие → реакция).
2. Альтернативные потоки (A1, A2...): отмены, пустые состояния, частичные данные.
3. Обработка ошибок: таблица «ошибка → код → сообщение → действие пользователя».

## 7. Интеграции

- Вызываемые API: метод, путь, таймаут, retry, поведение при недоступности.
