# Чеклист NFR для спецификации / сервиса

Правило: каждое NFR = **метрика + порог + способ проверки**. Пустые слова («быстро», «надёжно») запрещены.

## Производительность
- [ ] p50/p95/p99 latency по каждой операции (не «в среднем»)
- [ ] Целевая нагрузка: RPS/day peak (и как считан пик)
- [ ] Лимит размера payload, пагинация
- [ ] Время холодного старта (serverless/K8s autoscale)

## Доступность и отказоустойчивость
- [ ] Uptime SLO (% в месяц) и error budget
- [ ] SLA зависимостей -> расчёт составного SLA цепочки
- [ ] Graceful degradation: что отдаём при падении зависимости (кеш, fallback, 503)
- [ ] Retry/backoff/budget, circuit breaker — параметры
- [ ] DR: RPO / RTO, регулярность учений восстановления

## Масштабируемость
- [ ] Горизонтальное масштабирование: stateless? где состояние?
- [ ] Узкие места: БД (conn pool), брокер (партиции), single-writer
- [ ] План на 10x рост: что ломается первым

## Безопасность
- [ ] Аутентификация/авторизация (RBAC-матрица приложена)
- [ ] Данные в покое/в транзите: шифрование
- [ ] PII: перечень полей, хранение, срок ретеншена, право на удаление (GDPR)
- [ ] Секреты: хранилище, ротация; логи/метрики без PII и токенов
- [ ] Threat model проведена (см. шаблон)

## Наблюдаемость
- [ ] Золотые сигналы: latency, traffic, errors, saturation
- [ ] Структурированные логи + correlation-id
- [ ] Трейсинг сквозной (sync+async)
- [ ] Алерты: symptom-based, порог, маршрут дежурному; runbook на каждый

## Совместимость и эволюционируемость
- [ ] Версионирование API (semver; breaking policy)
- [ ] Обратная совместимость миграций БД (Expand-Contract)
- [ ] Поддержка N версий клиентов

## Комплаенс и юридическое
- [ ] Аудит-лог операций (кто/что/когда), неизменяемость
- [ ] Локализация данных (data residency)
- [ ] Согласия пользователя (для уведомлений — opt-in)

## Эксплуатация
- [ ] Стоимость на юнита (запрос/пользователь) оценена
- [ ] Runbooks, on-call, деградационные тумблеры (feature flags)
- [ ] Data retention и архивация
