## 2. Метод оценки

Выбрать и записать: planning poker (story points) / triage (S/M/L/XL) / аналогия с прошлым проектом / three-point (O, m, P): `E = (O + 4m + P)/6`.

## 3. Буферы и риски

| Риск | Влияние на срок | Буфер |
|---|---|---|
| Внешняя команда не отдаёт контракт | +5 дн | параллельно готовим mock по OpenAPI |
| Неизвестная легаси-миграция | +3 дн | time-box spike 2 дн |

## 4. Definition of Ready (вход в работу)

- AC написаны Gherkin, пройдены с PO
- UX-макеты утверждены
- Интеграционные контракты согласованы (INT-xxx)
- NFR заполнены по чеклисту
- Оценку даёт команда, а не один SA

## 5. Definition of Done

- Код + ревью + тесты (unit/contract/e2e по пирамиде)
- Документация API обновлена (OpenAPI diff)
- Метрики/логи/алерты добавлены
- План восстановления проверен; Expand-Contract соблюдён. Удаление данных не всегда обратимо, ограничения отката явно описаны
- Демонстрация на стенде, скрин AC-сценариев

## 6. Трекинг

План vs факт (burndown/циклы). После релиза — ретро: какие оценки соврали и почему -> обновить базу аналогий.
