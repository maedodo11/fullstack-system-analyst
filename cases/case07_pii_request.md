# Кейс 7. Запрос на персональные данные

## Ситуация

Маркетинг хочет витрину в BI: «возраст, город, телефон, число посещений» всех пациентов клиники для таргета SMS. Юрист занят, команда давит: «данные свои, внутреннее использование».

## Ваш ход

Проведите оценку как SA, владеющий privacy-чеклистом. Что разрешите, что завернёте, какие условия поставите?

## Разбор

1. **Правовое основание.** Обработка ПДн для маркетинга требует согласия (152-ФЗ / GDPR art. 6(1)(a)) с конкретизацией цели. «Внутреннее использование» не освобождает. Нет согласия на SMS-маркетинг → нельзя.
2. **Минимизация.** Даже с согласиями: телефон в витрине не нужен — сегмент «возраст+город+частота» строится без него. Решение: витрина без прямых идентификаторов; резолвинг сегмента в контакты — задача рассылочного сервиса, который сам знает телефоны.
3. **Хранение и доступ.** Ретеншен витрины (90 дней), RBAC: маркетологи видят сегменты, не выгружают CSV с ФИО; аудит-лог запросов.
4. **Opt-in как констрейнт:** флаг согласия из CRM фильтруется в SQL витрины, а не «надеемся на культуру».
5. **Реидентификация:** точный возраст+город+пол может уникализировать человека (k-анонимность) → возрастные группы 18-25..., минимальный размер сегмента.

**Итоговый компромисс:** витрина `patient_segments(segment_id, age_band, city, visits_bucket)` + сервис рассылок (резолвит сегмент → контакты, ведёт opt-out реестр, лимиты частоты SMS). Маркетинг получил задачу, privacy — гарантию.

**Типичные ошибки SA:** ограничиться вопросом «согласие есть/нет»; отдать витрину с прямыми телефонами «для удобства»; не предусмотреть право на удаление (erasure → сегменты должны перестраиваться).
