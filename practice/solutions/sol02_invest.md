# Решение 2. INVEST-декомпозиция эпика подписок

Истории (упорядочены по ценности):

1. **US-01.** Как пользователь, я вижу список моих активных подписок с частотой и темой — *MVP: уже даёт прозрачность, без write-операций.*
2. **US-02.** Я могу отписаться от одной рассылки мгновенно (one-click unsubscribe).
3. **US-03.** Я могу подписаться на доступную рассылку со страницы настроек.
4. **US-04.** Я могу выбрать формат (digest/individual) для активной подписки.
5. **US-05.** Все мои изменения подписок применяются немедленно и отражаются в письмах (сквозная проверка).
6. **US-06.** Админ видит журнал изменений подписок (audit trail).

Проверка по INVEST для US-02: Independent (не ждёт US-04), Negotiable (one-click или через подтверждение — обсуждаемо), Valuable (снижает churn и жалобы сразу), Estimable (~2 дня), Small (одна операция), Testable (AC: клик → письмо не приходит в течение часа; статус в UI обновлён).

**Разбор типичного плохого варианта:** одна история «управление подписками» со всеми CRUD + UI + email-сервис — нарушает Small и Testable, оценка невозможна, QA тестирует всё вместе в конце.

Приём декомпозиции: «по вертикали» (тонкий сквозной срез: UI→API→DB→email), а не «по горизонтали» (сначала весь UI, потом весь API).
