# Модуль 12. Процессы, Agile и инструменты аналитика

Как аналитик работает в команде: артефакты, ceremonies, тулинг, коммуникация.

## Теория

### 1. Роли и границы ответственности
- **Системный аналитик**: системные требования, интеграции, API-контракты, модели данных, постановки разработчикам.
- **Бизнес-аналитик**: процессы, бизнес-требования, стейкхолдеры.
- **Product owner**: приоритет ценности. В реальных командах роли смешаны — договаривайтесь о Definition of Ready.

RACI для фичи «рефанды»: R — аналитик+разработчики, A — PO, C — служба безопасности/поддержка, I — маркетинг.

### 2. Scrum/Kanban глазами аналитика
- Refinement: аналитик приносит story с AC до оценки; без этого оценка невозможна (Definition of Ready).
- Sprint: типовой поток задач аналитика — интервью → спецификация → review контрактов → приёмка UAT.
- Kanban: WIP-лимиты на этапе «спецификация в работе» — иначе 10 полу-документов вместо 3 готовых.

Разбор: команда тратила 40% спринта на уточнения требований «в процессе». Внедрили DoR-чеклист (есть AC, есть макет, определён источник данных, согласован контракт) → пустые уточнительные митинги упали вдвое.

### 3. Инструменты
| Задача | Инструменты |
|---|---|
| Backlog/трекинг | Jira, YouTrack, Linear |
| Знания | Confluence, Notion, Wiki.js |
| Диаграммы | draw.io, PlantUML, Mermaid, Camunda |
| Прототипы | Figma, Balsamiq |
| API | Swagger UI, Postman/Bruno, Stoplight |
| DDL/данные | dbdiagram.io, ERDPlus, DBeaver |
| Коммуникация | Slack/Teams + трединг задач из чата в трекер |

Хорошая привычка: диаграммы как код (PlantUML/Mermaid в git) — версионируются вместе с требованиями, пересобираются автоматически.

### 4. Жизненный цикл артефакта аналитики
Draft → Review (разработчики, QA, заказчик) → Approved → In development → Delivered → Maintained (living documentation). Антипаттерн: «ТЗ на 80 страниц, которое никто не читает после второй главы». Замена: тонкие спецификации + OpenAPI + Gherkin-тесты = исполняемые документы.

### 5. Оценка трудозатрат аналитических работ
Декомпозиция: интервью (N часов) + прототип + спецификация + ревью + поддержка разработки + тестовые сценарии + документация релиза. Правило: закладывайте 2–3 итерации уточнений; «согласование с заказчиком» — самая недооцениваемая статья.

### 6. Soft skills: техники
- Слушание и переформулирование («правильно ли я понял, что...»).
- Работа с «хочу кнопку» от заказчика → вопрос «какую проблему решаете?» → первоисточник требования.
- Фасилитация воркшопов: таймбокс, parking lot, фиксация решений протоколом.
- Письменные статусы: что сделано / риски / нужное решение — коротко.
