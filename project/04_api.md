# 4. Контракт API и поведение интерфейса

[Назад](03_data.md) · [Проект](README.md) · [Далее](05_processes.md)

Полный проверяемый контракт: [openapi.json](openapi.json), OpenAPI 3.1. Base URL учебный, сервер не развёрнут. Cookie-сессия задаётся системой входа; изменяющие запросы требуют CSRF-защиты. `X-CSRF-Token` проверяется сервером относительно сессии, а не просто на наличие.

| Операция | Назначение | Успех | Значимые ошибки |
|---|---|---|---|
| GET /slots | Слоты за указанный UTC-интервал (не более 7 суток), страница ≤100 | 200, items и next_cursor | 400 INVALID_RANGE, 401 |
| POST /appointments | Запись самого пользователя | 201 новая, 200 повтор | 409 SLOT_UNAVAILABLE / IDEMPOTENCY_CONFLICT, 400, 401, 403, 503 |
| GET /appointments/{id} | Своя запись | 200 | 401, 404 для чужой или отсутствующей |
| POST /appointments/{id}/cancel | Отмена своей записи | 200, включая повтор уже выполненной отмены | 401, 403 CSRF, 404, 409 CANCELLATION_CLOSED / INVALID_STATE |

## Семантика повтора

Область ключа — пользователь + операция + ключ. Тело сравнивается после нормализации по полям контракта. В течение 24 часов тот же ключ и slot_id возвращают исходный appointment_id с **текущим** статусом, даже если запись уже отменена; это повтор результата, а не новая запись. Конкурентный повтор ожидает завершение первой транзакции в пределах общего deadline; при превышении — 503 с Retry-After, клиент сохраняет ключ.

После истечения TTL гарантия повтора прекращается. Клиент сначала уточняет известную запись, а не генерирует новую попытку вслепую. Первая успешная транзакция сохраняет ключ вместе с записью; ключи запросов, отклонённых до создания, не резервируются. При новом сознательном выборе времени нужен новый ключ.

## Пример

```http
POST /appointments HTTP/1.1
Content-Type: application/json
Idempotency-Key: booking-demo-001
X-CSRF-Token: demo-session-bound-token
Cookie: session=demo-session

{"slot_id": 101}
```

```json
{"id": 501, "slot_id": 101, "status": "CONFIRMED", "version": 1}
```

## Состояния интерфейса

| Состояние | Что видит пациент | Действие |
|---|---|---|
| Загрузка | Индикатор и доступное текстовое сообщение | Дождаться результата |
| Список пуст | «На выбранные даты свободных слотов нет» | Выбрать другой период |
| Подтверждено | Номер, врач, локальное время и пояснение о SMS | Открыть свою запись |
| Конфликт | «Это время уже занято» | Обновить список, выбрать заново |
| Сеть прервалась | «Проверяем, создана ли запись» | Повторить с прежним ключом |
| Сбой SMS | Запись остаётся подтверждённой | Показать детали в кабинете |

Состояния не различаются только цветом; результат запроса объявляется assistive technology, фокус остаётся управляемым с клавиатуры.
